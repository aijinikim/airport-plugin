# 수업 정리 — airport-plugin 을 말로 시켜 만든다

44번 「Plugin 은 Skill · Hook · Agent · MCP 를 한 폴더로 묶어 구성한 것이다」의 실습 재료.
완성본이 이 레포다. 학생은 아래 프롬프트로 같은 것을 만들어 보고 이 레포와 비교한다.

## 필요한 도구

| 무엇 | 왜 | 준비 |
|---|---|---|
| Claude Code | 플러그인을 만들고 실행한다 | 설치 · 로그인 |
| Node.js 18 이상 | 스크립트 · 훅 실행 (내장 `fetch`) | `node -v` 로 확인 |
| 공공데이터포털 계정 + 서비스 키 | 승객예고 API(15095066) | 활용신청 → 일반 인증키 → `DATA_GO_KR_KEY` |
| 카카오 계정 + PlayMCP | 카카오톡 나와의 채팅으로 보내기 | 도구함에 「카카오톡 나챗방」 담기 → `/mcp` 인증 |
| GitHub 계정 | 마켓으로 나눠 쓰기 (선택) | 레포 하나 |

## 만드는 순서 — 프롬프트

한 번에 다 시키지 않는다. 한 단계마다 결과를 보고 다음으로 간다.

**① 뼈대**
```
airport-plugin 이라는 Claude Code 플러그인 뼈대를 만들어줘.
.claude-plugin/plugin.json 과 marketplace.json 까지.
```

**② 데이터 (스크립트)**
```
공공데이터포털 「인천국제공항공사_승객예고-출·입국장별」 API 로
오늘 T1 · T2 출국장의 시간대별 예상 승객 수를 받아서,
가장 붐비는 시간대 3개를 카톡용 4줄 메시지로 만드는 Node 스크립트를 scripts/ 에 만들어줘.
키는 환경변수 DATA_GO_KR_KEY 에서만 읽어.
```
→ 확인: 키 없이 실행하면 안내가 나오는지. 필드 이름은 포털 명세(Swagger)와 맞는지 **직접 대조**한다.

**③ Skill**
```
이 스크립트를 실행하고 결과를 카카오톡 나와의 채팅으로 보내는 airport 스킬을 만들어줘.
스크립트가 실패하면 숫자를 지어내지 말고 멈추게 해.
```

**④ Hook**
```
카카오톡으로 보내기 직전에 메시지가 4줄 형식이고 200자 이하인지 검사해서,
다르면 막는 PreToolUse 훅을 플러그인에 넣어줘.
```
→ 확인: 일부러 이모지를 넣은 메시지를 보내게 해서 막히는지 본다.

**⑤ MCP**
```
카카오 PlayMCP(https://playmcp.kakao.com/mcp)를 .mcp.json 으로 플러그인에 넣어줘.
```

**⑥ 되풀이 (시연)**
```
/loop 1h /airport-plugin:airport
```

## 구성요소 대응표

| 44번 그림의 칸 | 이 플러그인 | 왜 이걸로 |
|---|---|---|
| `plugin.json` → Plugin name | `airport-plugin` | 이름은 소문자 · 하이픈만 |
| Skill | `skills/airport/SKILL.md` → `/airport-plugin:airport` | 절차를 글로 남긴다 |
| Hook | `hooks/validate-kakao-format.js` | 프롬프트로 「형식 지켜」는 보장이 안 된다 — 코드로 막는다 |
| MCP server | `.mcp.json` (PlayMCP) | 카카오톡을 Claude 의 도구로 붙인다 |
| Subagent | 없음 | 일 하나짜리라 맡길 것이 없다 — 억지로 넣지 않았다 |

## 짚을 점

- **예상치다.** 실측 혼잡도가 아니다. 메시지 마지막 줄에 늘 적는다
- **키는 비밀이다.** 레포 · 대화 · 카톡 어디에도 안 붙인다
- 스킬에 「API 를 불러」라고만 쓰면 매번 다르게 부른다 — 스크립트로 고정했다
- 명세는 포털의 **OpenAPI 활용가이드(docx)** 가 1차 자료다. Claude 에게 그 파일을 주고 「이걸 참고해서」라고 시키면 필드 이름을 지어내지 않는다
- 인천공항은 승객예고 API, 김포·김해·제주 등은 한국공항공사 혼잡도 API(15159598)로 따로다
